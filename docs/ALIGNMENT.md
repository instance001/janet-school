# Janet School Alignment

## Purpose

Janet School is a standalone research apparatus for studying whether reusable structure,
transfer behavior, boundary pressure, anomaly clusters, and emergent structure
candidates appear when a deterministic MCM student is placed inside a controlled,
LLM-generated curriculum scaffold.

Janet School is not:

- an ed-tech product
- a chatbot shell
- an AI tutor for end users
- a curriculum-as-truth engine
- a proof system for confirmed abstraction
- a ChattyCog-dependent application

The application exists to generate careful evidence, not to market capability claims.

## Core Alignment Commitments

The implementation must preserve all of the following:

- Standalone-first build
- Deterministic MCM integrity
- LLM teacher outside the MCM core
- Full telemetry capture
- Append-only event storage
- Anomaly preservation
- Clear separation of confirmed, boundary, and emergent signals
- Provisional language in analysis and UI
- Human review over overclaiming

## Janet School Roles

### Deterministic MCM Student

The Janet-side student is the research subject. It must answer through deterministic,
inspectable logic paths using explicit memory, skill governance, policy checks,
refusal behavior, and full trace output.

The MCM student may:

- normalize and classify inputs
- read and write explicit memory with logs
- identify candidate deterministic skills
- enforce approval gates
- execute approved deterministic skills
- compose partial deterministic attempts
- refuse when uncertain or blocked

The MCM student may not:

- call an LLM inside its decision path
- inherit teacher answers
- mutate hidden state
- silently generalize beyond approved capabilities
- present uncertainty as confidence

### LLM Teacher

The teacher exists to generate curriculum and advisory teaching artifacts. It is a
stochastic proposal source, not a reasoning core for Janet.

The teacher may:

- generate curriculum drafts
- generate examples and questions
- generate feedback
- suggest remediation
- suggest transfer probes
- produce advisory notes and session summaries

The teacher may not:

- answer on Janet's behalf
- write to Janet memory
- rewrite or suppress telemetry
- determine final MCM outputs
- declare abstraction proven

### Human Operator

The human remains the governor of the system. Human review is required for:

- configuration approval
- skill approval changes
- interpretation of emergent candidate patterns
- release decisions
- architectural boundary decisions

## Research Posture

Janet School treats curriculum annotations as hypotheses about what an item may be
testing. Those annotations do not define what Janet actually did. The system should
be built to surface mismatches between intended structure and observed behavior.

All analysis language must remain provisional. Preferred wording includes:

- candidate
- possible
- flagged
- requires review
- unknown structure
- boundary pressure
- category mismatch
- emergent structure candidate

Avoid language that implies proof, confirmation, personhood, or educational success.

## Non-Goals For v0.1

- No ChattyCog integration
- No cloud teacher APIs
- No autonomous skill acquisition
- No hidden memory layers
- No vector-memory dependence inside the MCM core
- No GUI-first architecture
- No polished classroom framing
- No claim that one success demonstrates abstraction

## Acceptance Mindset

For v0.1, correctness means the system preserves boundaries, captures evidence, and
produces reproducible outputs. A modest but honest research rig is preferable to a
feature-rich system that compromises determinism or interpretability.
